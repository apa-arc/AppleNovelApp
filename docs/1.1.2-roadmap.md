# 1.1.2 开发计划：Kokoro 清理与在线 TTS 接管

> 本计划承接 1.1.1 延期项。1.1.1 先完成播放器、通用音频层、Gemini 实验、缓存和 OTA 验收；1.1.2 再处理 Kokoro 迁移，避免在当前稳定版本中提前删除现有听书能力。

## 版本目标

- 从 1.1.1 已验收的代码基础继续开发，不另起项目。
- 移除 Kokoro / Sherpa-ONNX 专属运行时与模型资源。
- 将最终通过费用、隐私、中文语音、多角色和真机验收的在线 TTS 服务接入完整听书流程。
- 继续保持用户无需自建服务器、不绑定银行卡/信用卡、不承担自动扣费风险。
- 如果没有符合条件的在线服务，不能为了完成版本目标而接入不合格服务；应保留 provider adapter 并明确说明阻塞项。

## 任务清单

### A. Kokoro 清理

- [ ] 删除 Kokoro 推理调用、模型资源、模型下载器、专属音色配置和 UI。
- [ ] 删除 Sherpa-ONNX 原生依赖、原生补丁脚本、专用构建 workflow 和不再使用的原生模块。
- [ ] 清理 Kokoro 专属缓存、设置和遗留 AsyncStorage/Keychain 键；提供安全迁移，不误删用户书架、阅读进度、订阅源和本地导入文件。
- [ ] 移除 playWavAudio 等仅为 Kokoro 保留的兼容命名，统一调用通用音频播放 API。
- [ ] 检查 iOS Pod、Xcode 工程、锁文件、CI workflow、依赖审计与 IPA 体积，确认无残留。

### B. 在线 TTS 正式接入

- [ ] 最终确认服务的免费规则、是否要求付款方式、超额行为、隐私条款、商用范围和模型可用性。
- [ ] API Key 不进入仓库、构建日志或普通偏好存储；若只能客户端持有用户 Key，明确说明客户端提取风险。
- [ ] 接入单人中文旁白和多角色对白；每位人物跨章节保持音色一致。
- [ ] 对白识别不确定时回退旁白，不猜人物身份。
- [ ] 长章节安全分段，处理速率限制、取消、超时、网络恢复、重试和断点续播。
- [ ] 输出音频接入通用播放器，保留后台播放、锁屏、进度、倍速、定时关闭和连续章节体验。
- [ ] 音频缓存按书籍、章节、服务/模型、音色和语速隔离，支持命中、失效、清理和容量管理。

### C. 验收

- [ ] 中文普通话长段落自然度试听。
- [ ] 旁白 + 至少两名角色的跨章节音色一致性测试。
- [ ] 多角色对白切换、标点/数字/英文/emoji/超长段落测试。
- [ ] 连续多章节播放、后台/锁屏、暂停恢复、来电/音频焦点中断测试。
- [ ] 免费额度耗尽、HTTP 429、401/403、断网、超时和取消场景测试。
- [ ] iOS 真机自签安装验收、OTA 更新兼容性检查、最终 IPA 构建和依赖审计。
- [ ] 全部通过后再更新版本号并正式发布；不发布开发预览版。

## 当前已知候选

- Gemini 3.8 Flash TTS：1.1.1 已有实验客户端和试听入口，但尚未完成真实 API / 账户免费资格 / 真实中文多角色 / 隐私评估与完整听书流水线验收。免费层不是无限永久承诺，不能预设为最终生产服务。
- Fish Audio：已有早期客户端原型，但免费开放期和长期可用性不满足当前生产门槛，除非政策发生可核验变化。
- 其他服务必须重新按用户硬性约束评估；不因已写代码就默认选用。

## 不得违反的约束

- 不绑定银行卡或信用卡。
- 不启用付费结算，不接受自动扣费风险。
- 不要求用户本地部署或维护服务器。
- 不把限时试用/有限免费额度描述为永久免费。
- 未有替代服务通过真实试听与真机验收前，不删除当前 Kokoro 代码。
