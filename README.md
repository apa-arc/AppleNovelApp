## 在线更新

项目已接入 Expo Updates 客户端能力和应用内更新入口。正式启用 OTA 前，还需要创建/绑定 EAS 项目并配置更新地址与发布通道，然后构建一次包含 expo-updates 的原生安装包。之后 JavaScript、界面样式和静态资源修复可通过 EAS Update 下发，用户无需重新安装。

- 更新检查：正式更新构建中会在启动后自动检查，也可在「我的」页面手动检查；开发预览环境不拦截
- 强制更新：发现可用 OTA 更新后锁定主界面，必须下载并重启到新版本；下载失败可重试，不能跳过
- 兼容保护：使用 fingerprint runtime version，避免将不兼容原生代码的更新下发给旧安装包
- 限制：原生模块、权限、Expo SDK 或底层依赖变更仍需重新构建安装

当前仓库尚未绑定 EAS projectId，因此更新服务暂时显示为待配置；不会伪造“已连通”或假装有更新可下载。已加入 `eas.json` 的 preview/production 通道，以及 GitHub Actions 手动发布工作流。完成 EAS 项目绑定后，在 GitHub 仓库 Secrets 中添加 `EXPO_TOKEN`，即可从 Actions 页面选择通道并发布 OTA 更新。首次仍需构建并安装一次包含 `expo-updates` 的正式包。

## 小说数据模型

`src/novel.ts` 定义统一的书籍摘要、详情、章节、正文、搜索分页和阅读进度类型。搜索结果可按规范化后的书名与作者合并，保留首个来源的详情链接，并补全更完整的简介和封面。阅读进度模型支持章节与段落索引，便于后续实现精确续读。

## 数据与听书

书架和阅读进度保存在设备本地，不会自动上传到服务器。听书目标采用同一模型的云端/本地双运行方式：联网时由服务端运行 Kokoro 多语言模型生成 AI 语音；只有用户主动选择声音并确认下载后，才下载兼容的本地模型；在线播放、启动 App、断网或引擎切换都不会触发自动下载。下载完成后，离线端使用同一模型和 speaker ID 生成声音，尽量保持音色一致。当前选定逻辑模型 `kokoro-multi-lang-v1_1`（中文+英文，103 个 speaker），对应的 sherpa-onnx int8 下载资产 ID 为 `kokoro-int8-multi-lang-v1_1`；上游压缩包约 147 MB（147,052,523 字节），一个模型包包含全部 103 个音色，下载一次后可在这些音色中切换，当前上游并未提供按单个 speaker 拆分的官方包。`src/speech-engine.ts` 负责引擎选择与文本分段，`src/speech-voice-catalog.ts` 维护稳定的模型/音色 ID、官方 103 位 speaker 名称及中英文性别分类、离线复用判断和云端请求载荷。注意：这只是共享模型/音色标识的架构基础，实际云端与本地听感仍可能因推理版本、采样率和音频后处理略有差异；模型下载策略已明确为手动触发并加入独立测试；手动下载状态机已覆盖确认、进度、暂停、恢复、失败重试、完成和显式删除；实际下载界面与原生下载器、原生推理、云端服务端接口和音频播放队列尚未接通。云端 API 密钥应由服务端保管，不写入 App 客户端。

## JSON 书源格式（当前版本）

在 App 的“书源”页粘贴 JSON 对象导入。字段均为必填项，网址必须使用 HTTPS 公网地址，不能包含账号密码，也不能指向 localhost 或局域网。示例：

```json
{
  "name": "我的书源",
  "baseUrl": "https://example.com",
  "searchUrl": "https://example.com/search",
  "bookUrl": "https://example.com/book",
  "chapterListUrl": "https://example.com/chapters",
  "chapterUrl": "https://example.com/chapter"
}
```

当前受限 HTTP 请求层只允许访问书源配置中声明的 HTTPS 域名，使用 GET、禁用凭据并阻止重定向，同时限制请求超时和响应文本大小。它目前只负责安全地取得响应，不会执行书源脚本；HTML/JSON 选择器解析、搜索结果映射、详情、目录和正文流程仍未完成。示例域名不可直接用于搜索。请只配置你有权访问且允许自动化访问的站点。

## 项目原则

本项目只实现阅读器与合法书源规则管理，不托管未经授权的小说正文。接入书源前应确认目标站点的使用条款及内容授权情况。
